Happy-Path LITE Benchmark — H1 & H2 (2026-06-11)

Directional pass (n=1) of the two claim-carrying flows from research/15, run with 37 real subagents (885,831 tokens, ~25 min). Both arms make byte-identical changes from identical seeds, so the comparison isolates the medium, not agent skill. No variance claims from LITE.

H1 — Revision loop: patch vs rewrite CONFIRMED — promote to HEAVY

Eight small edits to a 25-field data-bound CRM report. Primary metric: characters the agent had to author per hop. Ad-hoc ran best-case (surgical splicing, not full rewrite).

Where CLAN wins: data-bound fields — one patch-data updates both the data and the bound {{key}} view, while ad-hoc must edit two files and often re-types the same supplied text. Where it loses: appending one item to an array — patch-data's RFC-7396 merge-patch replaces arrays, forcing the agent to re-author every prior element (finding F14). Fidelity: 8/8 changes present in both arms, zero meaningful unintended diffs.

H2 — Long chain: find the crossover NOT CONFIRMED in LITE

Ten-hop analyst chain, data/notes only until the final hop. Primary metric: injected context per hop.

No genuine crossover. For the data-only interval (hops 1–9) CLAN's injected context stayed 1.5–2.3× above ad-hoc, and CLAN's marginal growth (453 chars/hop) was actually steeper than ad-hoc's (366) — because CLAN re-injects the growing decision chain each hop. The apparent hop-10 crossover is an artifact: the ad-hoc lead-partner authored a full HTML report, ballooning its snapshot. The guide alone is ~7,948 chars — larger than the entire skip-guide injection, so a cold agent reads 3.5× more than ad-hoc. Honest read (matches research/14): at small structured-findings scale CLAN is net injected-context overhead, not savings. The crossover needs larger per-hop payloads and/or chain pruning — flagged for HEAVY.
