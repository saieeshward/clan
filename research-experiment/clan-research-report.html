CLAN-Based Multi-Agent Pipelines vs Plain File Handoff: A Controlled Comparison

Report Writer Agent v1·2026-05-31·5-Agent Sequential Pipeline

Abstract

This report presents a controlled empirical comparison between two multi-agent document-production pipelines: a CLAN-based pipeline using structured TOON-encoded context propagation, schema enforcement, and cryptographic provenance, and a baseline pipeline using plain file handoff. Both pipelines executed the same five-agent sequence — Research, Regulatory, Strategy, Writer, and QA — to produce a personal finance document on investing €100 in Dublin, Ireland. CLAN completed the task 36% faster (353.8s vs 554.4s), produced a substantially smaller and more structured final artifact (19KB vs 48KB), and maintained full auditable provenance. The baseline achieved a slightly higher QA quality score (0.95 vs 0.85) and consumed fewer total tokens (14,748 vs 17,255). Trade-offs and practical implications are analysed in detail.

Methodology

Both tracks executed a strictly sequential five-agent pipeline: Research → Regulatory (pinned in CLAN) → Strategy → Writer → QA (pinned in CLAN). CLAN carried structured YAML/TOON-encoded context with JSON Schema validation at every hop. The baseline passed plain markdown/HTML files between agents. Measurements recorded: input/output bytes and tokens per agent, wall-clock time, provenance availability, human view availability, and schema enforcement.

Key Findings

⏱ Execution Time: CLAN 36% faster

CLAN completed in 353.8s vs 554.4s. The dominant driver was Agent 1: the baseline used live web-search tooling, consuming 249s (45% of its total time). CLAN Agent 1 operated from pre-seeded context and completed in 71s. CLAN’s QA agent was 2.2× faster (14s vs 31s), consistent with receiving a smaller, already-structured input.

🔢 Token Consumption: CLAN 17% more total, 28% fewer output

CLAN consumed 17,255 total tokens vs 14,748 for baseline. However, CLAN produced only 4,812 output tokens vs 6,732 (+28% more efficient). CLAN’s higher input token count (+55%) reflects CLAN envelope overhead. The baseline’s low Agent 1 input token count understates its true cost — external web search tool calls are not fully reflected.

📐 Context Fidelity: CLAN coherent growth; Baseline drifted

CLAN context grew coherently 5,508B → 21,850B (3.97×), with structured accumulation. The baseline exploded from 332B to 48,364B (145×) primarily due to Agent 4 passing the full HTML to the QA agent. A concrete fidelity issue was observed: Strategy agent allocation percentages drifted from Research agent values — a data contract violation that CLAN’s schema enforcement would have caught at the hop boundary.

🔐 Provenance: CLAN cryptographic; Baseline zero

CLAN maintains a full 5-entry decision chain with SHA-256 integrity on all artifacts. Two agents are pinned — their outputs are cryptographically sealed and cannot be silently regenerated. The baseline offers zero provenance: no record of which agent produced which decision, and re-running would produce a semantically different output with no audit trail.

✓ Schema Enforcement: CLAN at every hop; Baseline none

CLAN enforced JSON Schema at every hop, guaranteeing data contract compliance before passing context downstream. The baseline enforced no schema, leading to the allocation-percentage drift observed in the Strategy agent.

Discussion

CLAN Pipeline

Strengths

  • 36% faster end-to-end
  • 61% smaller final artifact (19KB vs 48KB) with more information
  • Full cryptographic provenance with pinned decisions
  • Schema enforcement prevents silent data drift
  • 28% fewer output tokens
  • Clean separation of data layer and presentation layer

Limitations

  • 55% higher input token cost due to envelope overhead
  • Lower QA score (0.85) — PRSI 2024 not surfaced in human view
  • Requires CLAN-aware runtime for encoding/decoding
  • Learning curve for YAML/TOON-encoded context

Baseline Pipeline

Strengths

  • Higher QA score (0.95) — prose richness and completeness
  • Lower total tokens (14,748)
  • Zero tooling dependency — any LLM can participate
  • Natural prose accumulation without schema constraints

Limitations

  • 4.5× slower when live web search is required
  • Zero provenance — non-starter for regulated workflows
  • Data drift between agents with no detection mechanism
  • Bloated 48KB HTML artifact with no structured data layer
  • 6,732 output tokens (vs 4,812) — much is markup boilerplate

Conclusion

CLAN prioritises structure, auditability, and determinism; the baseline prioritises simplicity and prose richness. Use CLAN when regulatory compliance, data integrity, or programmatic downstream consumption is required. Use the baseline when content generation quality and simplicity are the primary criteria and provenance is not required. A hybrid approach — CLAN structure with richer prose within schema-compliant fields — may close the QA score gap while retaining CLAN’s auditability and speed advantages.

Use CLAN when…
  • Regulatory compliance or auditability required
  • Pipeline outputs consumed programmatically
  • Data integrity across agent hops must be guaranteed
  • Execution speed matters; external tool calls can be avoided
  • Long-running pipelines where decisions must be reproducible
Use Baseline when…
  • Pure content generation with no downstream machine consumption
  • Live web research is unavoidable
  • Simplicity of implementation is paramount
  • Maximum prose quality is the primary success criterion
  • Token cost (not wall-clock time) is the binding constraint
